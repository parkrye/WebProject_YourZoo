### 폰트 외곽선 수정 (M0 회귀)

반투명하게 만들어 테두리가 갉아먹힌 것처럼 보였다. 배경만 투명하면 되므로 페더링을 제거하고,
잉크 판정 알파를 `24 → 6` 으로 낮추고, 검출 프레임에 2px 여백을 줬다.
분할 시 경계 컬럼을 버리던 것도 앞쪽 밴드에 포함시켰다.
→ 36자 중 33자가 잉크 손실 0. `V` `W` `X` 는 원본에서 획이 맞닿아 있어 경계를 공유한다.

### 🔴 되짚을 실수: 시트의 알파를 눈으로 판단했다
폰트 시트를 뷰어로 보니 갈색 배경이 보여서 "불투명 배경"으로 단정하고 RGB 플러드필 컷아웃을 넣었다.
실제로는 처음부터 RGBA 였고 배경은 전부 `alpha 0`, 갈색은 투명 픽셀의 잔여색이었다.
알파를 무시한 플러드필이 글자의 어두운 아웃라인까지 배경으로 오인해 지웠고,
그게 "글자가 잘려 보인다"의 원인이었다. 사용자가 두 번 지적해서야 알파 채널을 확인했다.

**교훈: 새 에셋은 렌더 결과가 아니라 `mode` 와 알파 히스토그램으로 판단한다.**
실제로 알파가 없던 건 `bg_area_ice`, `sprite_prop_desert`, `sprite_human_visitor` 셋뿐이었다.

### 레이아웃이 계속 넘쳤던 진짜 원인
요청서에 템플릿 칩이 들어오자 양쪽 칸이 모두 넘쳤다(665px vs 393px).
팝업을 키우고 칩을 옮겨도 해결되지 않았는데, 원인이 둘이었다.

1. 9-슬라이스 배율 상한을 1.15 로 뒀더니 **큰 팝업일수록 테두리가 두꺼워져** 내용 공간을 먹었다 → 상한 1.0
2. `BitmapLabel` 이 캔버스 높이를 글자 크기의 **1.35배**로 잡았다. 이 폰트는 디센더가 없어

### 🔴 서식지가 어디서 정해지는지 화면에 없었다
`FREE` 템플릿으로 만든 동물이 하늘·물에 배치되지 않는다는 지적을 받았다.
원인은 **습성 프리셋이 서식지까지 결정**하고 있었다는 것이다.
`FREE` 는 프리셋을 건드리지 않으므로 기본값 `BEAST`(=`LAND`)가 그대로 남았고,
바꾸려면 `TRAITS` 에서 `BIRD`/`FISH` 를 고르거나 `CUSTOM` 으로 들어가야 했는데
그 연결이 UI 어디에도 드러나지 않았다.

→ `HABITAT` 을 `TEMPLATE` 바로 아래 독립 필드로 올렸다. 템플릿이 기본값을 제안하되
언제든 바꿀 수 있다. 식성(`HERB`/`CARN`/`OMNI`)은 배치와 무관하다는 것도 문서에 못박았다.

### 드래그 고스트가 커서에서 어긋났던 이유
고스트는 `.screen` 안에 있고 그 조상 `.stage-view` 에 `transform: scale()` 이 걸려 있다.
**transform 이 걸린 조상은 `position: fixed` 의 기준이 된다.**
그래서 뷰포트 좌표를 그대로 넣으면 스테이지 스케일만큼 밀린다.
캔버스 `getBoundingClientRect` 로 논리 좌표로 환산해 넣도록 고쳤다.

### 파츠를 자르지 않고 부위별로 움직이는 법
템플릿이 "어느 위치에 어느 부위가 있는지" 약속해 주므로 부위별 애니메이션이 가능하다.
그런데 그림을 파츠 rect 로 **잘라 붙이면 이음매가 드러난다** — 사람이 그린 경계는 제각각이다.

대신 이미지를 **띠로 나누고 띠마다 다르게 밀었다.** 자르는 게 아니라 미는 것이라
이음매가 생기지 않는다. 원본을 통째로 깔고 그 위에 띠만 변형해 덧그려서
띠가 비운 자리에 구멍이 나지도 않는다.

`alternate` 플래그로 조각을 홀짝으로 갈라 반대로 움직이면 **네발 걸음**이 된다.
`cycles: 0` 이면 범위가 한 덩어리로 움직이고(귀, 날개), 0 보다 크면 파동이 흐른다(꼬리, 몸통).

### 손님 크기를 뭉개고 있었다

**투명 여백을 잘라낸 뒤 크기를 맞춰 버린 셈이다.**
프레임 높이를 시트 최대 높이로 나눈 비율을 곱해 원본 비율을 되살렸다.

스크립트에 `pause` 가 없어 그대로 창이 닫혔다. 원인을 볼 새가 없었다.
→ 모든 종료 경로에 `pause` 를 넣고, 시작 전에 포트를 검사해
이미 켜진 서버가 있으면 끄고 계속할지 물어본다.

## M12 — 조명 층 분리와 편의  ← *완료*

- [x] 조명을 `sky` / `area` / `fence` 로 나누고 **층마다 반응 정도를 다르게**
- [x] 물 동물 크기 `0.15 → 0.12` (원근 배율 1.18 이 더 곱해진다)
- [x] 탭이 뒤로 가 있어도 시계가 흐른다
- [x] 요청서 초안이 세션 동안 유지된다
- [x] 드래그 중 트레이·울타리가 내려가 물 영역이 보인다

### 조명 사양 (M12 에서 두 번 고쳤다)
처음엔 한 겹으로 화면 전체를 덮었고, 다음엔 층을 나눴지만 방향이 어긋났다 —
하늘 밝기를 **되살리는** 쪽으로 만들었는데 요구는 시간대 밝기를 **약간 적용**하는 것이었고,
우리 안은 위에서 내려오는 전면 그라디언트였는데 요구는 **부분적으로 비추는 조명 영역**이었다.

최종: 하늘 = 밝기 약간 / 우리 안 = 밝기 약간 + 색 약간 + 빛 웅덩이 / 울타리 밖 = 밝기·색 그대로.

### 울타리를 별도 레이어에 그린 이유
"울타리는 시간에 그대로, 우리 안은 약간만" 을 한 겹 조명으로는 만들 수 없다.
울타리+손님을 오프스크린 캔버스에 따로 그린 뒤 조명을 먹여 합성한다.
`multiply` 가 알파도 함께 곱하므로 울타리 모양대로만 색이 먹고 뒤의 우리는 그대로 남는다.

### 초안을 스토어로 올린 이유
그림 한 장에 몇 분이 걸리는데 제출하려다 돈이 모자라 창을 닫으면
이름도 그림도 습성도 통째로 사라졌다. 세이브에는 넣지 않는다 —
그림이 Blob 이라 직렬화가 번거롭고, 미완성 초안까지 저장할 만큼 중요하지 않다.

### 손님을 붙박이로 세우지 않는다
목표 인원만큼 세워 두면 같은 사람이 계속 서 있는 게 눈에 띈다.
저마다 22~65초 머물다 돌아가게 두고 **들어오는 속도만** 목표에 맞췄다.
평형에서 `평균 인원 = 스폰 속도 × 평균 체류` 이므로
스폰 간격을 `평균 체류 / 목표` 로 잡으면 인원이 목표 주위에서 오르내린다.

앞뒤로도 흩어 세운다. 발 위치를 `0.97~1.10` 사이에 두고 앞사람은 크게(×1.10),
뒷사람은 작게(×0.84) 그린다. 한 줄로 세우면 관람로가 종잇장처럼 평평해 보인다.

### 검증 서버는 29877 에서만
`taskkill /IM node.exe` 로 사용자가 돌리던 다른 서버들과
`YourZoo 실행.bat` 창까지 말없이 죽인 적이 있다.
검증은 `npm run preview:test` (29877) 로 띄우고 **그 PID 하나만** 정리한다.

## 우선순위 근거

M0 의 **폰트 컷아웃**과 M1 의 **레이어 합성**이 이 프로젝트의 두 급소다.
둘 다 에셋 자체의 제약에서 오는 리스크이고, 실패하면 대체 에셋이 필요해진다.
따라서 게임 로직(M2~)보다 **먼저** 검증한다.
